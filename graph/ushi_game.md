# 牛ゲー（差分制約）のメモ

> **Source:** https://github.com/hitori6541/lib  
> **File:** `graph/ushi_game.md`

## 最適化問題からグラフの問題へ

次の最大化問題を、有向グラフの最短経路問題に置き換える。

$$
\begin{aligned}
\text{Maximize}\quad & x_t-x_s \\
\text{Subject to}\quad & x_j-x_i\le c_{ij}\quad\text{（各制約）}
\end{aligned}
$$

**制約 $x_j-x_i\le c$ → 辺 $i\to j$、重み $c$。**

このグラフ全体に負閉路がなく、$s$ から $t$ に到達できるとき、最大値は $s\to t$ の最短距離になる。

## お気持ち：3変数の具体例

$$
x_1-x_0\le3,\qquad x_2-x_1\le4,\qquad x_2-x_0\le10
$$

のもとで $x_2-x_0$ を最大化する。

- 直接の制約から $x_2-x_0\le10$。
- 最初の2本を足すと $x_2-x_0\le3+4=7$。
- $(x_0,x_1,x_2)=(0,3,7)$ で全制約を満たすので、最大値は **7**。

グラフでは $0\to1$（重み3）、$1\to2$（重み4）、$0\to2$（重み10）。
直接行くより、頂点1を経由したほうが厳しい上界になる。

高校数学の線形計画法として見るなら、$x=x_1-x_0$, $y=x_2-x_0$ と置く。

$$
x\le3,\qquad y\le x+4,\qquad y\le10
$$

この領域で直線 $y=k$ を上へ動かすと、$(x,y)=(3,7)$ で最大値7を取る。

## 最適化問題の定式化とコツ

まずすべて **「差 $\le$ 定数」** に直してから辺を張る。

| 制約 | 変形 | 辺（重み） |
| --- | --- | --- |
| $x_j-x_i\le c$ | そのまま | $i\to j$（$c$） |
| $x_j-x_i\ge c$ | $x_i-x_j\le-c$ | $j\to i$（$-c$） |
| $x_j-x_i=c$ | 上限と下限の2本 | $i\to j$（$c$）、$j\to i$（$-c$） |
| $x_i\le x_j$ | $x_i-x_j\le0$ | $j\to i$（0） |

### 厳密不等号：整数なら1ずらす

差が整数で、$c$ も整数の場合：

$$
x_j-x_i<c\iff x_j-x_i\le c-1
$$

$$
x_j-x_i>c\iff x_j-x_i\ge c+1\iff x_i-x_j\le-c-1
$$

実数の厳密不等号には、この変換は使えない。適当な小さい $\varepsilon$ を引く方法も、一般には同値にならない。

### 最小化：目的関数を反転する

同じ制約のもとで

$$
\min(x_t-x_s)=-\max(x_s-x_t)=-\mathrm{dist}(t,s)
$$

つまり、**始点と終点を逆にして最短距離を求め、答えの符号を反転**する。
制約の辺は変えない。
全体に負閉路がないことが前提で、$t\to s$ に到達不能なら下に有界でない。

### 定数との比較：基準となる変数を用意する

基準変数 $x_r=0$ として、定数も差分制約で扱う。

| 制約 | 辺（重み） |
| --- | --- |
| $x_i\le a$ | $r\to i$（$a$） |
| $x_i\ge a$ | $i\to r$（$-a$） |
| $x_i=a$ | 上の2本 |

基準頂点も他の頂点と同じように扱い、得た解の全変数から $x_r$ を引いて0に合わせる。

## グラフの世界でのコツ

### なぜ最短経路で求まるか

経路上の制約を足すと中間変数が消え、$x_t-x_s\le$ 経路の重みになる。
したがって、最短経路が最も厳しい上界を与える。

| 状況 | 最大化問題の結果 |
| --- | --- |
| グラフのどこかに負閉路がある | 制約全体が矛盾し、解なし |
| 全体に負閉路がなく、$s\to t$ に到達可能 | 最大値は $\mathrm{dist}(s,t)$ |
| 全体に負閉路がなく、$s\to t$ に到達不能 | 上に有界でない（いくらでも大きくできる） |

すべての変数に同じ定数を足しても制約と目的関数は変わらないので、$x_s=0$ としてよい。
$s$ から到達できる頂点では $x_v=\mathrm{dist}(s,v)$ と置くと制約を満たし、上界を達成する。
到達不能な頂点は、全体の実行可能解をもとに、その頂点群の値を一括で十分大きくずらせばよい。
到達可能な頂点から到達不能な頂点への辺は存在しないため、この拡張ができる。

### 探索アルゴリズムの選び方

| グラフ | アルゴリズム | 計算量 |
| --- | --- | --- |
| 負辺なし | Dijkstra | $O((N+M)\log N)$（二分ヒープ・重複辺をまとめる通常の実装） |
| 負辺ありの一般グラフ | Bellman-Ford | $O(NM)$（辺の走査） |
| DAG（負辺も可） | トポロジカル順に最短距離DP | $O(N+M)$ |

## 考察・実装のコツ

### 全体の矛盾判定と、目的の最短距離を分ける

1. **全体の矛盾判定**：Bellman-Fordの初期距離を全頂点0にする。全辺を走査する処理の $N$ 回目にも更新があれば負閉路あり。
2. **最大値を求める**：矛盾がなければ、距離を $s$ だけ0、ほかは $\infty$ に初期化し直して最短距離を求める。
3. $t$ の距離が $\infty$ なら上に有界でない。そうでなければその距離が答え。

全頂点0での開始は、仮想始点から全頂点へ重み0の辺を張ることと同じ。
この初期化なら、$s$ から到達できない場所の負閉路も検出できる。
全辺を直接走査する実装なら、初期化も含め $O(N+NM)$。更新がない回で終了してよい。

**仮想始点を追加した状態の距離を、そのまま $x_t-x_s$ の最大値に使わない。**
仮想始点は全体の矛盾判定・実行可能解の構成用で、目的の $s\to t$ の最短距離とは別。
制約が必ず矛盾しないと保証されているなら、全体の矛盾判定は省ける。

### クラスの使い方

実装：[ushi_game.py](ushi_game.py) の `UshiGame`。変数と定数は整数、頂点は0始まり。
距離の初期値は `10**18`。各単純経路の重みの絶対値がこれ未満であることを前提とする（例えば `N * max(abs(c)) < 10**18` なら十分）。
追加の引数順は **`(j, i, c)`** で、`x[j] - x[i]` を指定する。

```python
ug = UshiGame(3)
ug.add_le(1, 0, 3)   # x[1] - x[0] <= 3
ug.add_le(2, 1, 4)   # x[2] - x[1] <= 4
ug.add_lt(2, 0, 11)  # x[2] - x[0] < 11（整数なので <= 10）

assert ug.is_valid()
assert ug.solve_maximize(0, 2) == 7
assert ug.solve_minimize(2, 0) == -7
assert ug.solve_maximize(2, 0) == "inf"
assert ug.solve_minimize(0, 2) == "-inf"
```

`add_ge(j, i, c)` は `>= c`、`add_gt(j, i, c)` は `> c` を追加する。
制約の追加は各 $O(1)$（償却）。追加した制約は矛盾していても残る。

| 最大化メソッド | 最小化メソッド | 使用条件 |
| --- | --- | --- |
| `solve_maximize(s, t)` | `solve_minimize(s, t)` | Bellman-Ford版と同じ |
| `solve_maximize_bellman_ford(s, t)` | `solve_minimize_bellman_ford(s, t)` | 一般グラフ |
| `solve_maximize_dijkstra(s, t)` | `solve_minimize_dijkstra(s, t)` | 変換後の全辺が非負 |
| `solve_maximize_dag_dp(s, t)` | `solve_minimize_dag_dp(s, t)` | 変換後のグラフ全体がDAG |

どの方式も `x[t] - x[s]` を最適化する。有限なら `int`、非有界なら文字列 `"inf"` / `"-inf"`。
矛盾した制約でsolveすると `ValueError`。Dijkstra版は負辺がある場合、DAG DP版は閉路がある場合も `ValueError`。
例外を処理しなければAtCoderではREになる。

`is_valid()` は全体の負閉路を判定し、`True` / `False` を返す。
Bellman-Ford版のsolveは内部でこれを呼ぶので、事前の呼び出しは必須ではない。
Dijkstra版・DAG DP版では、その使用条件から負閉路がないと分かるため、Bellman-Fordの判定を省く。
判定結果とトポロジカル順は再利用し、`add_*` で制約を追加したら破棄する。
`edges`・`graph` は直接変更せず、追加には `add_*` を使う。

実装の計算量は、Bellman-Ford版が $O(N+NM)$、Dijkstra版が $O(N+M\log(M+2))$、DAG DP版が $O(N+M)$。
Dijkstra版は重複辺を保持するヒープ実装なので、$M$ を使って表記している。記憶領域は各 $O(N+M)$。

### 使うときの確認

- 最大化したい差はどちら向きか。$x_t-x_s$ なら $s\to t$。
- 下限制約を反転するとき、辺の向きと重みの符号を両方変えたか。
- 厳密不等号を1ずらせる整数の問題か。
- 負閉路を全体で確認する必要があるか。
- 「矛盾して解なし」と「有界でない」を区別したか。
